## SECTION 2 — Task 33: incident recovery (why :3000 was down + the durable fix)

Symptom (04:19Z): main :3000 dead (connection refused) while parity :3210 alive.
Root-cause timeline (dmesg + logs):
- [22297 ≈ 02:38] OOM killer killed the ORIGINAL :3000 next-server (PID 1547,
  anon-rss 1.87GB) — the parity instance's startup/compile (02:37) pushed the
  4GB box over the edge. The two dev servers had never coexisted at full memory.
- [28471 ≈ 04:24] first relaunch attempt OOM-killed during page compile
  (parity still held 1.5GB; Turbopack compile spike did not fit).
- Attempts 3-4 + a control experiment (same project on :3220) all died within
  45-150s by SILENT SIGKILL — no OOM record, no crash trace, log truncated
  mid-line. Diagnosis: the Bash tool's process reaper kills shell-descendant
  processes shortly after their launching command ends, regardless of
  nohup/setsid/port (setsid execs in place — the chain stays a shell descendant).
  Counter-evidence that isolated the criteria: the parity instance (launched
  02:37 by the previous session via dfork_launch.py — a TRUE double-fork, child
  reparented to init) survived the same reaper for 2h.
FIX (both durable, in persistent storage):
1. research/dfork-launch.sh — persistent double-fork launcher:
   subshell backgrounds the target and exits instantly → child reparents to
   init (PPID=1, tini) → escapes any descendant-walk reaper. Verified: launched
   main :3000 this way, root ancestry confirmed PPID=1, survived every
   reaper window that killed all prior attempts.
2. NODE_OPTIONS heap caps so both servers coexist on the 4GB box:
   main --max-old-space-size=1024 (RSS 1927MB → 1156MB),
   parity --max-old-space-size=1536 (RSS 1112MB warm).
   Steady state: both 200, headroom 1.45GB. OOM risk closed.
Recovery commands (post-reboot, absolute paths):
  /home/z/my-project/research/dfork-launch.sh /home/z/my-project /dev/null \
      env NODE_OPTIONS="--max-old-space-size=1024" bun run dev
  /home/z/my-project/research/dfork-launch.sh \
      /home/z/my-project/mini-services/hyper3d-clone-dev /dev/null \
      env NODE_OPTIONS="--max-old-space-size=1536" bun run dev
  (each package script tees its own dev.log; warm with one GET / each)
