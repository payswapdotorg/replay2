## 3. Task packet

**WFX-028 — Short Feed.** The client-facing Short Feed model: vertical card
stack, swipe navigation semantics, rapid candidate replacement, session-aware
re-ranking triggers, and engagement event emission contracts. Framework-neutral
core + thin presenter (React types only if already available; NO new deps —
same rule as WFX-026/027). NO data fetching; NO provider logic; NO video
rendering. Realization: `packages/experience/src/short/`.

Build these modules (file names may differ; structure required):

1. **`stack.ts`** — `ShortFeedStack`: the vertical card stack model:
   `{ items: ShortCard[]; cursor: number; prefetchAhead: number }` with typed
   operations: `swipeNext()`, `swipeBack()` (bounded), `replaceAt(cursor,
   replacement)` (rapid candidate replacement), `insertAhead(items)` (when the
   OS replenishes). Every operation returns the NEW stack (immutable style) +
   a typed `StackEvent` for the trail. Backward swipe is bounded (first card ⇒
   typed no-op with reason — never wraps).

2. **`card.ts`** — `ShortCard` view-model: item (orientation enforced
   vertical-first ordering — vertical items ranked ahead, others typed-tailed
   with reason), duration, title/topic overlay data, engagement affordances
   (like/save/share — mapped to the WFX-005 action use-case input types),
   realization badge, a11y labels (typed, every card).

3. **`replacement.ts`** — rapid candidate replacement policy (pure):
   `planReplacement(stack, osFeed, sessionState)`: when the OS supplies a fresh
   short-surface page, decide which unwatched cards beyond the cursor get
   replaced: watched/skipped ⇒ replaceable; unwatched within prefetch window ⇒
   kept; deterministic merge order; the PLAN is typed data (list of
   replacements + reasons) — the stack applies it.

4. **`session-ranking.ts`** — session-aware re-ranking triggers (pure):
   `shouldRerank(sessionState, events): RerankDecision`: triggers on N swipes
   or M seconds or a like/save signal (thresholds from policy — reuse intent
   graph policy types); decision carries the exact intent-update inputs the
   WFX-011 inference would derive from the accumulated events (typed, additive
   only — anti-tunnel-vision: re-ranking DEMOTES nothing below visibility,
   it reorders ahead-of-cursor candidates only). NEVER silently optimizes
   session length against attention mode (attention-policy law).

5. **`events.ts`** — engagement emission contract: `shortFeedEvents(stack,
   interaction)` → the exact frozen `EntertainmentEvent`s (progress with
   payload percent, complete, skip, like, save, share) the app layer should
   emit — typed payloads, sessionId wired, ready for the WFX-005 EventSink.

6. **`presenter.ts` (+ `react.ts` if react types available)** —
   `createShortFeedPresenter(deps)`: builds the initial stack from an OS
   FeedPage (short surface), exposes typed state transitions for the UI
   (current card, next card, transition reasons), placeholder states
   (loading/error/empty typed).

7. Tests in `packages/experience/tests/short.test.ts` (bun:test):
   - Stack operations: swipe next/back bounds, replace, insert immutability +
     trail events.
   - Vertical-first ordering with typed-tailed non-vertical items.
   - Replacement policy: watched ⇒ replaceable, unwatched-prefetch ⇒ kept;
     golden merge outputs.
   - Rerank triggers: N-swipe, M-second, engagement-signal thresholds; decision
     payload = additive intent inputs only; no below-visibility demotion.
   - Event emission: every interaction type → exact frozen event payloads.
   - A11y labels on every card.
