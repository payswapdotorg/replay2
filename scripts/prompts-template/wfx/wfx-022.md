## 3. Task packet

**WFX-022 — External action synchronization.** The outbox/synchronization layer
that mirrors user actions (like/save/follow/comment) to external sources with
retries, idempotency, and typed reconciliation — WITHOUT real network calls
(drivers injected). Realization: `packages/actions/src/sync/` (the
`@wfx/actions` package scaffold exists from WFX-001).

Build these modules (file names may differ; structure required):

1. **`outbox.ts`** — `ActionOutbox`: the transactional outbox record store
   (pure, in-memory with the same interface a durable store would implement):
   - `enqueue(entry: OutboxEntry): OutboxRecord` — every action gets a
     deterministic id + `status: "pending" | "in-flight" | "delivered" |
     "failed" | "unsupported" | "conflict"`, `attempts: number`,
     `nextAttemptAt: string`, `idempotencyKey: string`.
   - `IdempotencyKey` = hash over (userId, connectorId, action verb, target
     externalRef, clientRequestToken) — duplicate enqueue with the same key
     RETURNS the existing record (typed `duplicate` marker) — never
     double-executes.
   - `due(now)` — pending/in-flight records past `nextAttemptAt`.

2. **`dispatch.ts`** — `SyncDispatcher`: drives the outbox against a connector
   registry (the MERGED WFX-012 registry API):
   - `tick(now)`: for each due record: resolve connector; if the connector
     lacks the action's capability → mark `unsupported` (typed, terminal);
     else call `executeAction` through the SDK convention; map result:
     ok → `delivered` (+ `ActionReceipt` stored), typed unsupported →
     `unsupported` (terminal, reason stored), error with retryability →
     attempt++ with exponential backoff (deterministic: base × 2^attempts,
     capped; clock injected), non-retryable → `failed` (terminal, error stored).
   - Max attempts (default 5) → `failed` with exhausted-reason.
   - Every transition appends to an audit `SyncLog` entry (timestamped via
     injected clock, old-state → new-state, cause).

3. **`reconcile.ts`** — `reconcile(outbox, connector, userId)`: compares
   local delivered actions against `readLibrary`-style connector state where
   the connector exposes it; drift (marked delivered locally but absent
   remotely) → typed `ReconciliationDrift` entries with a `resolution`
   suggestion ("re-enqueue" | "accept-remote" | "manual") — NEVER auto-mutates:
   reconciliation is REPORTING, resolution is caller policy.

4. **`drivers.ts`** — typed `SyncDriver` interface (the seam where a real
   networked connector adapter plugs in) + `createFixtureDriver(script)`:
   deterministic scripted outcomes per idempotency key (ok / unsupported /
   retryable-error / non-retryable-error / timeout) for tests. NO real network.

5. Tests in `packages/actions/tests/sync.test.ts` (bun:test):
   - Idempotency: duplicate enqueue never double-delivers (same record returned).
   - Capability honesty: read-only reference connector ⇒ every mutating action
     lands `unsupported` terminal with reason.
   - Retry: retryable error at attempt k ⇒ backoff schedule exact values
     (2^k deterministic), attempts cap → failed-exhausted.
   - Non-retryable → immediate failed.
   - Audit log: every transition recorded old→new with cause.
   - Reconcile drift detection: delivered-local/absent-remote flagged with
     suggestion; no auto-mutation (outbox unchanged by reconcile).
   - Golden flow: enqueue → 2 retryable failures → success on 3rd → delivered
     with receipt stored.
