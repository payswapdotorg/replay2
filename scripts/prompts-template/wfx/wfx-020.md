## 3. Task packet

**WFX-020 — Candidate retrieval/index.** The source-neutral retrieval stage that
feeds the Recommendation OS: an in-memory candidate INDEX over the Entertainment
Graph + connector search results, preserving every capability datum. TypeScript
types + pure logic + fixtures ONLY (no I/O, no network, no provider logic).
Realization: `packages/recommendation/src/retrieval/`.

Build these modules (file names may differ; structure required):

1. **`candidate.ts` — the retrieval unit.** `EntertainmentCandidate` already
   exists as a lane-A extension type in `packages/domain/src/contracts/extensions.ts`
   — import it; do NOT redefine it. Enrich with retrieval context:
   `RetrievedCandidate { candidate: EntertainmentCandidate; sourceRealizations: SourceRealization[]; matchedObjectives: string[]; retrievedAt: string; }`
   — capability data from every realization preserved verbatim.

2. **`index.ts` — the candidate index.** `CandidateIndex` (pure, in-memory):
   - `ingest(items: EntertainmentItem[], realizations: SourceRealization[])` —
     bulk load; duplicate realizations (same connectorId+externalRef) deduplicated
     keeping the freshest.
   - `query(q: RetrievalQuery): RetrievedCandidate[]` where `RetrievalQuery`
     includes free-text `text?`, `canonicalType?`, `orientation?`,
     `durationRangeMs?`, `connectorId?`, `requiredCapability?`, `limit`.
   - Text matching: deterministic, case-insensitive, tokenized substring over
     canonical titles + topic/creator names from the graph module. NO external
     search libs, no fuzzy deps — simple, typed, tested.
   - `requiredCapability` filters on REALIZATION capabilities (a movie whose only
     realization lacks `playNative` must NOT match a `playNative` query) — this is
     the "preserving capabilities" law.
   - An empty index returns `[]` — never throws for emptiness. Invalid query
     shapes throw typed `RetrievalError` with field details.

3. **`ingest-connectors.ts` — connector result → index bridge.**
   `ingestConnectorResults(index, results: SearchResult[], itemFor: (r) => EntertainmentItem | null)`:
   pure adapter that folds a connector's search output into the index. Connector
   results that cannot be mapped to a canonical item are counted in a typed
   `IngestReport { ingested: number; skipped: number; skipReasons: string[] }` —
   NEVER silently dropped.

4. **`intent-filter.ts` — intent-aware pre-filtering (RETRIEVAL SIDE ONLY).**
   `rankForIntents(candidates, intents: UserIntent[])` — STABLE, additive
   ordering: candidates matching more/stronger intents rank earlier; ties keep
   insertion order. CRITICAL LAW: this NEVER removes candidates and NEVER
   narrows the pool — filtering-out is the Recommendation OS policy stage's job
   (WFX-021). Anti-tunnel-vision: retrieval stays wide.

5. **`fixtures.ts`** — deterministic fixture data: ≥12 entertainment items across
   all 7 canonical types, ≥18 source realizations across 3 fake connector ids
   with DIFFERENT capability sets (one native-capable, one embed-only, one
   browser+external), 5 user intents across scopes. NO randomness.

6. **`packages/recommendation/src/index.ts`** — append exports (this barrel
   already exists; add your module exports — keep any existing lines intact).
