## 3. Task packet

**WFX-029 — Library/history client.** The client-facing library + watch-history
VIEW MODEL: unified "My Stuff" over (a) connector-synced library entries
(WFX-022 outbox state), (b) local watch history derived from the event stream,
(c) background-completed downloads (WFX-024). Framework-neutral core + thin
presenter (React types only if already available; NO new deps — same rule as
WFX-026/027/028). Realization: `packages/experience/src/library/`.

Build these modules (file names may differ; structure required):

1. **`model.ts`** — `LibraryView` sections (typed): `SavedSection` (entries
   grouped by user collections/lists from LibraryEntry data), `ContinueSection`
   (resume candidates: incomplete watches with position + progress ratio),
   `FinishedSection` (completed watches + completed downloads), `DownloadsSection`
   (WFX-024 CompletionEvents joined to items). Each section: rows with item,
   realization badges, source icons (connector displayNames), last-touched time.

2. **`history.ts`** — watch-history derivation (pure): `deriveWatchHistory(events,
   sessions)`: fold the frozen event stream (start/progress/complete/skip) +
   PlaybackSessions into per-item `WatchState { itemId; lastPositionMs;
   completionRatio; lastWatchedAt; status }` — progress events update position,
   complete sets status, skip marks skipped-but-resumable. Deterministic fold;
   out-of-order events handled by occurredAt ordering (tie-break by sequence
   input index, documented).

3. **`merge.ts`** — the unification: `mergeLibraryViews(connectorEntries,
   watchHistory, completions)`: same canonical item appearing in multiple
   sources MERGES into one row (source badges union); conflicts (remote says
   removed, local watch state exists) ⇒ typed `ConflictRow` with suggestions —
   never silently dropped, never auto-resolved.

4. **`commands.ts`** — library commands client model: `planLibraryCommand(intent)`:
   typed plan for save/remove/move-to-list actions — which WFX-005 use-case to
   call, which WFX-022 outbox entry will result (idempotency key preview),
   optimistic local state transition, and rollback plan if the outbox entry
   lands `failed`/`unsupported`. Optimistic UI MODEL only — no mutation here.

5. **`presenter.ts` (+ `react.ts` if react types available)** —
   `createLibraryPresenter(deps)`: assembles LibraryView from the three sources,
   section ordering policy (Continue first, then Saved, Downloads, Finished),
   placeholder states (loading/error/empty typed), a11y labels on every row.

6. Tests in `packages/experience/tests/library.test.ts` (bun:test):
   - History derivation: golden folds for start/progress/complete/skip
     sequences; out-of-order tolerance; multi-session resume.
   - Merge: cross-source union rows; conflict rows typed with suggestions.
   - Sections: ordering, empty-section suppression, badge correctness.
   - Command planning: optimistic transition + rollback plan for each terminal
     outbox state; idempotency-key stability for identical intents.
   - A11y labels on every row.
