## 3. Task packet

**WFX-014 — Native media engine adapter.** Build
`packages/native-media/src/engine/` — the adapter layer that bridges the frozen
`NativeMediaEngine` interface to a real engine boundary. The REAL Rust engine is a
separate later deliverable; this adapter defines the process/transport boundary and
ships a fully functional IN-PROCESS SIMULATION engine clearly typed as such:

1. `src/engine/process.ts` — `NativeEngineProcess` interface: the boundary a real
   engine subprocess (Rust, later) will implement:
   `spawn(config: EngineConfig): EngineHandle` where `EngineHandle` has
   `send(command: EngineCommand): Promise<EngineEvent>`, `onEvent(handler)`,
   `terminate()`. `EngineConfig { socketPath?: string; binaryPath?: string;
   cacheDir: string; maxCacheBytes: number }`. `EngineCommand` / `EngineEvent` are
   JSON-serializable DTOs (define them: open/seek/prioritize/pause/resume/close +
   progress/buffered/state-changed/error events). This is the wire contract the
   Rust service will speak — version it (`PROTOCOL_VERSION = 1`).
2. `src/engine/simulation.ts` — `createSimulationEngine(config): NativeMediaEngine`
  — a TEST/DEV engine implementing the FROZEN `NativeMediaEngine` interface with
  simulated behavior: deterministic buffering progression (timer-driven, no I/O),
  pluggable fake assets registry (magnet/localPath → simulated piece map, total
  bytes, durationMs), seek/prioritize/pause/resume/close honored with state
  transitions through the WFX-004 session FSM, range reads served from the
  simulated piece buffer with correct byte offsets. Clearly typed + documented
  as SIMULATION (never production). Reuse WFX-004's error taxonomy for failures.
3. `src/engine/adapter.ts` — `createEngineAdapter(process: NativeEngineProcess):
   NativeMediaEngine` — adapts ANY EngineProcess (including a future real one) to
   the frozen engine interface: command marshalling (DTOs), event → session state
   mapping, timeouts with typed ENGINE_TIMEOUT errors, process crash detection
   (`onEvent` error/exit → all live sessions → failed with INTERNAL, typed).
   This proves the wire contract round-trips: the adapter + a `createInProcessEngineProcess()`
   (a NativeEngineProcess backed by the simulation engine, in-process pipe, no
   subprocess) must behave identically to the simulation engine directly.
4. `src/engine/cache.ts` — local cache policy: `CachePolicy { maxBytes; evictOrder:
   'lru' | 'fifo' }`, `CacheTracker` (pure accounting: track/evict decisions,
   no I/O — the real engine owns the bytes; this module only computes policy).
   `shouldAdmit(tracker, incomingBytes)`, `evictList(tracker, incomingBytes)`.
5. Tests (bun:test) under `packages/native-media/tests/engine.test.ts`: process DTO
   round-trip (command/event JSON serialization), simulation engine (open →
   buffering → playing progression with fake asset; seek/pause/resume/close state
   transitions per FSM; range reads correct bytes; typed errors for unknown assets),
   adapter (in-process process + adapter behaves like direct simulation — property:
   same command sequence → same final states; process error → sessions failed typed),
   cache policy (admission under budget, LRU/FIFO eviction order, zero-budget
   rejection).
