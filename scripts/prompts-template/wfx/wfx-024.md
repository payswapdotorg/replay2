## 3. Task packet

**WFX-024 — Background completion + storage policy.** The policy engine that
decides what keeps downloading when playback pauses/ends, what gets evicted, and
what persists — plus the completion state machine driver. Pure TypeScript +
deterministic tests. Realization: `packages/native-media/src/background/`.

Build these modules (file names may differ; structure required):

1. **`policy.ts`** — `BackgroundPolicy` (typed, validated):
   - `CompletionPolicy`: `{ mode: "always" | "wifi-only" | "never" | "charging-only";
     maxConcurrentCompletions: number }` — defaults validated; OS-constrained
     platform hints are INPUTS (network class, charging state), never assumptions.
   - `StoragePolicy`: `{ maxCacheBytes: number; protectedItems: string[]; evictOrder:
     "lru" | "fifo"; minFreeBytes: number }` — reuses the WFX-014 `CacheTracker`
     accounting (import; never reimplement).
   - `decideCompletion(session, policy, environment): Decision` — environment:
     `{ networkClass: "wifi" | "cellular" | "offline"; charging: boolean }`.
     Output typed: `{ action: "continue" | "pause" | "cancel"; reason: string }`
     — e.g. wifi-only + cellular ⇒ pause (RESUMEABLE, never cancel) with reason.
     Terminal sessions (complete/failed) ⇒ action "cancel" (nothing to do) with reason.
   - `decideEviction(tracker, incomingBytes, storage): EvictionPlan` —
     protected items NEVER evicted (typed refusal with reason when impossible);
     plan = ordered victim list until minFreeBytes satisfied; deterministic.

2. **`completion-driver.ts`** — `createCompletionDriver(engine, policy, clock)`:
   - `onSessionBackground(session)`: apply decideCompletion; continue ⇒ keep
     scheduling via the MERGED WFX-023 scheduler tick contract (background
     fairness — reduced horizon, never starved); pause ⇒ engine.pause (typed
     envelope, failures recorded); cancel ⇒ engine.close.
   - `onEnvironmentChange(environment)`: re-evaluate ALL paused-for-policy
     sessions (wifi returns ⇒ resume). Policy transitions are always typed +
     logged in a `BackgroundLog` (audit trail: session, transition, cause).
   - Completion detection: session reaches `complete` ⇒ evict-from-active,
     mark persistent per StoragePolicy.protectedItems, emit typed
     `CompletionEvent { sessionId; assetId; completedAt; totalBytes }` to an
     injected `CompletionSink` — NO hidden callbacks.

3. **`storage.ts`** — `StorageGovernor`: wraps CacheTracker + StoragePolicy:
   - `admit(assetId, bytes)`: below ceiling ⇒ ok; over ⇒ eviction plan first
     (decideEviction), apply typed, then admit; impossible ⇒ typed refusal
     (never silently over-ceiling).
   - `release(sessionId)`: session cache freed on cancel/failed per policy.
   - Stats snapshot: bytes used, per-asset, evictions count — observable.

4. Tests in `packages/native-media/tests/background.test.ts` (bun:test):
   - Completion decision matrix: every mode × every environment (golden
     actions+reasons); terminal sessions cancel.
   - Wifi-only pause is resumable: environment change wifi ⇒ resume; the log
     records both transitions with causes.
   - Concurrency cap: >maxConcurrentCompletions ⇒ excess paused with reason,
     FIFO release order when one completes.
   - Eviction: protected never evicted (impossible ⇒ typed refusal); LRU/FIFO
     order exact; minFreeBytes respected.
   - Storage admit over-ceiling: plan-then-admit exact byte math.
   - Completion event emitted exactly once per completing session.
   - Engine failure during pause/close: typed, logged, driver survives.
