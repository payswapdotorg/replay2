## 3. Task packet

**WFX-023 — Deadline-aware playback scheduler.** The pure scheduling brain that
decides WHICH pieces to prioritize WHEN, per active session, from playback
position + bitrate + buffer state, and drives `engine.prioritize` with computed
deadlines. TypeScript + pure logic + deterministic simulation tests ONLY.
Realization: `packages/actions/src/scheduler/` — NO wait, this is native-media
adjacent: `packages/native-media/src/scheduler/` (same lane B package; the
scheduler serves native sessions directly).

Build these modules (file names may differ; structure required):

1. **`model.ts`** — `PlaybackDemand`: `{ sessionId; positionMs; playbackRate;
   bitrateBps; bufferAheadMs; stallBudgetMs }` + `SessionPriority`
   (foreground > background; deterministic weight per state from the session FSM).
   `SchedulerConfig`: `{ horizonMs; safetyMarginMs; maxDeadlineBatch; backgroundRateFactor }`
   with validated defaults.

2. **`plan.ts`** — `planPriorities(demand, config, nowMs): PieceDeadline[]` — PURE:
   - Compute the playback deadline of each needed piece: pieces are consumed at
     a deterministic timeline (positionMs + k×pieceDurationMs); deadline =
     consumption time − safetyMargin − networkEstimateMs (estimate INJECTED as a
     parameter, default a fixed constant — no hidden latency probes).
   - Foreground sessions: full horizon. Background sessions: horizon ×
     backgroundRateFactor, and their deadlines shift later (never starve, never
     preempt foreground).
   - Output sorted by deadline ascending, capped at maxDeadlineBatch; the NEXT
     IMMEDIATE piece (deadline ≤ now) is always first with a hard deadline.
   - Edge cases typed: non-playing sessions yield an EMPTY plan (paused/
     complete/failed need nothing); expired deadlines are clamped to now with a
     `late` marker in the plan entry.

3. **`drive.ts`** — `createScheduler(engine, config, clock)` — the stateful loop
   driver (no real timers — `tick(sessions: PlaybackDemand[])` called by the host):
   - Gathers demands, computes plans per session (foreground first), merges into
     one `prioritize` batch per session (the engine API is per-session), calls
     `engine.prioritize(sessionId, deadlines)` through the MERGED service
     convention (ServiceResponse envelope; typed failures recorded, engine
     errors NEVER crash the tick).
   - Maintains a `SchedulerStats` snapshot: pieces scheduled, late pieces,
     per-session plan sizes, last tick time — observable by tests/telemetry.
   - One tick never schedules beyond the horizon; repeated ticks with unchanged
     demands are IDEMPOTENT (same batch — no deadline drift without clock movement).

4. **`stall-guard.ts`** — `shouldStallProtect(demand, stats)`: pure predicate +
   typed recommendation (`{ protect: boolean; reason: string; suggestedActions:
   ("reduce-bitrate" | "pause-prefetch" | "extend-horizon")[] }`) when the
   projected buffer underruns stallBudgetMs. Feeds WFX-024 later; here it is
   the typed signal layer.

5. Tests in `packages/native-media/tests/scheduler.test.ts` (bun:test):
   - Plan golden outputs: fixed demand/config/clock → exact deadline lists.
   - Foreground vs background weighting; background never preempts foreground.
   - Immediate piece first; late clamping; batch cap.
   - Idempotent ticks (same batch twice).
   - Engine failure during prioritize: tick survives, stats record the typed error.
   - Stall guard: projected underrun → protect=true with reasons/actions;
     healthy buffer → false.
   - Non-playing sessions: empty plans.
