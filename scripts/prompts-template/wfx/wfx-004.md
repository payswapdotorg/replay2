## 3. Task packet

**WFX-004 — Native media service contract.** This is the SERVICE BOUNDARY around
the frozen engine interface — TypeScript types + pure logic + fixtures ONLY. You are
NOT implementing the actual media engine (that is WFX-014, Rust later). Build
`packages/native-media/src/`:

1. `src/session.ts` — session state machine: `resolving → buffering → playing ⇄
   background`, terminal `complete | failed` (from the frozen
   `NativeMediaSession.state` union). Export `SESSION_STATES`, a typed transition
   table `ALLOWED_TRANSITIONS`, `canTransition(from, to)`, `transition(session, to)`
   (pure: returns new session object or throws `InvalidTransitionError`), and a
   `makeSession(input)` factory with validation.
2. `src/errors.ts` — error taxonomy: `NativeMediaErrorCode` enum/union:
   `INVALID_INPUT | UNSUPPORTED_SOURCE | NOT_FOUND | IO_ERROR | VERIFICATION_FAILED |
   RANGE_NOT_SATISFIABLE | SESSION_CLOSED | ENGINE_TIMEOUT | INTERNAL`; class
   `NativeMediaError extends Error` carrying `{ code, detail?, sessionId?,
   retryable: boolean }` plus a `isRetryable(code)` table. Type guard
   `isNativeMediaError(x)`.
3. `src/range.ts` — the local HTTP range contract (consumed later by WFX-015's
   gateway): `RangeRequest { sessionId, startByte, endByte? }`, `RangeResponse {
   sessionId, startByte, endByte, totalBytes, contentType, data (Uint8Array) }`,
   `parseRangeHeader(header: string): { startByte; endByte? } | null` (standard
   `bytes=a-b`/`bytes=a-`/`bytes=-suffix` forms), `makeRangeResponse(...)`,
   `contentRangeHeaderValue(resp)`, and `satisfiable(request, totalBytes)` predicate.
4. `src/service.ts` — the service boundary interface: `NativeMediaService` — the
   request/response envelope the engine adapter (WFX-014) will implement over the
   frozen `NativeMediaEngine`:
   `open(req: OpenSessionRequest): Promise<ServiceResponse<NativeMediaSession>>`,
   `control(sessionId, command: PlayCommand)` where `PlayCommand = { kind: "play" |
   "pause" | "resume" | "seek"; positionMs?: number } | { kind: "prioritize";
   deadlines: { piece: number; deadlineMs: number }[] } | { kind: "close" }`,
   `status(sessionId)`, `range(req: RangeRequest)` — all returning
   `ServiceResponse<T> = { ok: true; value: T } | { ok: false; error:
   NativeMediaError }`. Include `OpenSessionRequest` (magnet? torrentBytes? localPath?
   — matching the frozen engine's open() input, at least one present, validated).
   Define this as a TYPE-ONLY interface + a `createNativeMediaService(engine:
   NativeMediaEngine): NativeMediaService` pure adapter that wraps ANY engine
   implementation (including a test double) with the envelope, validation, error
   mapping, and session-state enforcement (control on a closed/failed session →
   typed SESSION_CLOSED error, seek to negative → INVALID_INPUT, etc.).
5. `src/fixtures.ts` — test fixtures: `stubEngine(): NativeMediaEngine` — an
   in-memory engine double (clearly a TEST FIXTURE: simulated buffering progress,
   controllable state, no I/O), plus `sampleSessions`, `sampleErrors`,
   `sampleRangeRequests`. Fixtures are exported for tests, never wired as production.
6. `src/index.ts` — public entry re-exporting everything.
7. Tests (bun:test) under `packages/native-media/tests/`: session transitions
   (legal path resolving→buffering→playing→background→playing→complete; illegal
   e.g. resolving→complete throws), error taxonomy (codes, retryable table, guard),
   range parsing (all three header forms + malformed → null + unsatisfiable),
   service adapter (open validates input; control/pause/seek map to engine calls;
   closed session → SESSION_CLOSED; negative seek → INVALID_INPUT; engine throw →
   mapped INTERNAL/ENGINE_TIMEOUT error envelope), fixtures sanity.
