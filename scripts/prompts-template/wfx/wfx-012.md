## 3. Task packet

**WFX-012 — Connector registry + credential storage.** Build
`packages/connectors/src/auth/` (new subdirectory in YOUR lane's package):

1. `src/auth/secrets.ts` — a credential vault interface with an in-memory encrypted
   implementation: `CredentialVault` with `store(connectorId, kind, secret): SecretHandle`,
   `retrieve(handle): string | null`, `delete(handle)`, `list(connectorId)`.
   `SecretHandle` is an opaque reference (never the secret itself). The in-memory
   implementation (`createInMemoryVault()`) stores secrets XOR-obfuscated with a
   per-vault random key and ZEROES plaintext buffers on delete — document clearly
   that production deployments must back this with a real secret manager (the
   interface is the deliverable, the in-memory vault is a typed, honest default).
   Secrets NEVER appear in toString/JSON/inspect output (implement and test that).
2. `src/auth/session.ts` — `AuthSession` state machine per connector:
   `signedOut → authorizing → signedIn` (+ `expired`, `failed`), with
   `transition()` validation (illegal transitions throw typed `AuthStateError`),
   `isUsable(state)`, and expiry timestamps (`expiresAt` → auto-`expired` via
   `refresh(now)`).
3. `src/auth/flows.ts` — typed auth flow descriptors matching the frozen
   `ConnectorDescriptor.auth` union: `none | oauth | device | local`:
   `AuthFlow` discriminated union — `{ kind: 'none' }`, `{ kind: 'oauth';
   authorizationUrlTemplate: string; scopes: string[]; tokenRefresh: boolean }`,
   `{ kind: 'device'; verificationUrlTemplate: string; pollIntervalSeconds: number }`,
   `{ kind: 'local'; method: 'token' | 'userpass' }`. `flowFor(descriptor): AuthFlow`
   — deriving the flow from a registered descriptor, validating template shape
   (contains `{...}` placeholders).
4. `src/auth/service.ts` — `ConnectorAuthService`: binds vault + sessions + registry:
   `beginAuth(ctx, connectorId)` → returns the flow + a `pendingAuthId` (for oauth/device
   the CALLER completes the external handshake — this service NEVER handles user
   credentials directly per product-boundaries; it only stores what the caller hands it
   post-handshake via `completeAuth(pendingAuthId, secret)`), `signOut(connectorId)`
   (vault delete + session → signedOut), `authState(connectorId)`. All typed results —
   unknown connector, wrong-flow completions, and expired pendings are typed errors.
5. Tests (bun:test) under `packages/connectors/tests/auth.test.ts`: vault (store/
   retrieve/delete/list; handle opacity; secrets absent from JSON.stringify and
   util.inspect; delete zeroes), session FSM (legal/illegal transitions, expiry
   refresh), flows (derivation per descriptor.auth kind; template validation errors),
   service (begin/complete happy path per flow kind; wrong-flow complete → typed error;
   unknown connector → typed error; signOut clears both).
