## 3. Task packet

**WFX-027 — Long-form Watch Feed.** The client-facing Watch Feed model: episodic
continuity rows, resume affordances, playback-quality/audio/subtitle control
descriptors, and the view-model assembly that turns an OS `FeedPage` into
presentable `WatchFeedView` data. Framework-neutral core + thin React presenter
(React types only if already available in the workspace — see WFX-026 note; do
NOT add dependencies to packages/experience). NO data fetching (data injected);
NO provider logic. Realization: `packages/experience/src/watch/`.

Build these modules (file names may differ; structure required):

1. **`view.ts`** — `WatchFeedView` model: hero section (resume-or-start
   primary item), continue-watching row (ordered by last-watched recency,
   each entry: item, resumePositionMs, completion ratio, realization badge),
   episodic rows (series → next-episode adjacency from graph relations via
   injected `RelationsPort`), topic rows. Every row: typed `FeedRow` with
   `kind`, items, and a `reason` string (explainability: "continues your
   session intent 'sci-fi'").

2. **`continuity.ts`** — episodic continuity engine (pure): given a series'
   episode graph + watch history (events), compute the NEXT episode, resume
   points, "New season" markers, and a `ContinuityCursor` (seriesId,
   nextEpisodeId, resumePositionMs). Binge-chain visibility (N-next preview)
   bounded by attention mode (mindful: fewer, immersive: more — reuse the
   intent-graph policy types from `@wfx/domain`).

3. **`controls.ts`** — quality/audio/subtitle control DESCRIPTORS: typed
   `PlaybackControlSet` generated from realization capabilities + device
   profile: available quality tiers (from capabilities), audio tracks and
   subtitle tracks as DECLARED data (providers declare tracks; this model
   composes them — no probing). Unavailable controls are typed-absent (never
   greyed-out lies): the descriptor carries exactly what the realization
   supports.

4. **`presenter.ts` + `react.ts`** — `createWatchFeedPresenter(deps)` returning
   a view-model builder (`build(feedPage, context): WatchFeedView`), and the
   thin React component if react types are available in the workspace (else
   documented wiring like WFX-026). Presenter handles: row ordering policy,
   resume badge thresholds (>5% and <95% watched), placeholder states
   (loading/error/empty typed), and accessibility labels (every card: title,
   position description, action label — typed `A11yLabel` on each entry).

5. **`resume.ts`** — resume orchestration (pure): `planResume(item, history,
   surfaceResolution)` → either continue-session (existing PlaybackSession
   found) or start-fresh; emits the exact frozen `EntertainmentEvent` payload
   the WFX-005 playback use-case should emit (typed, not fired — firing is
   the app layer's job).

6. Tests in `packages/experience/tests/watch.test.ts` (bun:test):
   - View assembly: OS FeedPage → WatchFeedView golden output (hero, continue
     row order, episodic rows).
   - Continuity: mid-series history → correct next episode + resume; finished
     series → "start next season"/"complete" markers; empty history → pilot.
   - Binge-chain visibility bounded by attention mode (mindful < immersive).
   - Controls: capability-honest descriptor (native realization ⇒ full set;
     embed-limited ⇒ typed-absent tracks).
   - Resume thresholds: <5% watched = start-fresh; 5–95% = resume; ≥95% =
     next-episode.
   - Explainability: every row has a non-empty reason.
   - Accessibility labels present on every entry.
