## 3. Task packet

**WFX-026 — In-app browser surface.** The CONTAINED browser session model: a
typed, host-embeddable specification of the in-app browser surface with persistent
WebFlix shell, provider handoff, and security isolation. This item delivers the
SURFACE MODEL + state machine + policy + a headless-capable embeddable web
COMPONENT (custom element or React component — `packages/experience` stays
framework-neutral: ship a framework-neutral core + a thin React wrapper module
clearly isolated for later app wiring). NO actual browser engine control (that is
the platform adapter layer: Tauri WebView / Android WebView / iOS WKWebView —
injected as a typed `BrowserHost` port). Realization:
`packages/experience/src/browser/`.

Build these modules (file names may differ; structure required):

1. **`host.ts`** — `BrowserHost` port (the platform seam): `{ open(url,
   options): BrowserSessionHandle; close(handle): void; onNavigation(handle,
   cb): void; evaluate?: (handle, script) => Promise<unknown> }` +
   `BrowserSessionHandle { id: string; url: string }`. Plus
   `createFixtureBrowserHost(navigationScript)` — deterministic scripted
   navigations for tests. NO real webview.

2. **`session.ts`** — `BrowserSurfaceSession` FSM: `closed → opening → ready →
   navigating → ready → … → closed`; typed transitions, invalid transitions →
   typed errors. Holds: target realization URL, provider domain (parsed +
   validated), session identity, and the PERSISTENT SHELF: the WebFlix shell
   state (surface chrome visibility, positionMs heartbeat) that survives
   navigation. Navigation events update the FSM; provider-handoff (user clicks
   out to full provider site) emits a typed `ProviderHandoffEvent` with the
   outbound URL — OBSERVED, never blocked (provider security boundary), but
   recorded for the session trail.

3. **`isolation.ts`** — security isolation POLICY (pure):
   - `IsolationPolicy { allowedDomains: string[]; blockFileUrls: true;
     blockPrivateNetworks: true; restrictCookies: "isolate" }` — validate
     realization URLs against the policy: file:// rejected, private/loopback
     IPs rejected (SSRF guard, pure IP parsing), non-allowed domains → typed
     `isolated-refused` with reason. Origin allow-list is per provider
     connector id (typed map supplied by caller).
   - Cookie/storage isolation is ASSERTED by policy, ENFORCED by the host
     (documented contract: hosts receive `restrictCookies` in open options and
     MUST honor it — the typed contract is this item's deliverable).

4. **`shell.ts`** — the persistent shell model: `SurfaceChromeState` (compact/
   expanded/hidden), `resumePositionMs` heartbeat payload, typed
   `ShellCommands` (back-to-feed, minimize, close). Pure state + reducers.

5. **`component.ts` + `react.ts`** — framework-neutral component logic (a
   `createBrowserSurface(deps)` controller binding host+session+shell) and a
   THIN React wrapper (`<BrowserSurface>` for later app use) — the wrapper may
   import `react` types ONLY if the workspace already provides react in app
   packages; otherwise ship the controller only and document the wiring (do NOT
   add react to packages/experience dependencies — lane rules; if react types
   are unavailable, put the wrapper in a comment-documented form inside
   component.ts and note it in your report).

6. Tests in `packages/experience/tests/browser.test.ts` (bun:test):
   - FSM: legal path golden sequence; illegal transitions typed-rejected.
   - Isolation: file/private-IP/non-allowlisted → typed refusals; allowlisted
     https → ok. (Pure URL/IP parsing — no network.)
   - Provider handoff: outbound click OBSERVED + recorded, never blocked.
   - Shell persistence across navigation (chrome state + resume heartbeat).
   - Fixture host: scripted navigation sequence drives the FSM end-to-end.
   - Cookie isolation contract present in every open() call options.
