## 3. Task packet

**WFX-040 — Cross-platform clients.** Capability PARITY layer + the three client
shells (apps/web, apps/desktop, apps/mobile — scaffolds exist from WFX-001):
a shared client runtime that adapts platform capabilities into the shared
contracts, plus minimal-but-real client entrypoints for each platform proving
the SAME Experience API drives all three. NO provider logic, NO engine
implementation. Realizations: `apps/web/src/`, `apps/desktop/src/`,
`apps/mobile/src/` + shared `apps/web/src/shared/` (or a `packages/experience`
public import — do NOT create a new package).

Build these modules (file names may differ; structure required):

1. **`capabilities.ts`** (shared, in apps/web/src/shared) — platform capability
   PROFILES + adapters: `WebCapabilities` (browser-constrained: no native media,
   embed/browser/external modes, localStorage-backed), `DesktopCapabilities`
   (full power: native mode available, filesystem, background completion,
   casting-ready), `MobileCapabilities` (native media, OS-constrained
   background: cellular/charging inputs honored, reduced cache ceilings). Each
   profile produces a `DeviceCapabilities` compatible with the domain
   `canPlay` contract (compile-time assertion). Plus typed `PlatformAdapter`:
   storage (K/V port with per-platform fixture impls), lifecycle (foreground/
   background events typed), browser host (reuses the WFX-026 BrowserHost port).

2. **`runtime.ts`** (shared) — `createClientRuntime(platform, ports)`: binds the
   WFX-005 Experience API + WFX-025 resolver + feeds to the platform profile:
   one typed façade `ClientRuntime` with `getFeed(surface)`, `startPlayback`,
   `library()`, `actions()`, `surface` — the SAME calls on all platforms; only
   the capability profile differs. Error taxonomy passthrough (typed).

3. **`apps/web/src/main.ts`** — the web client entry: instantiates the runtime
   with WebCapabilities + fixture ports; a minimal index.html if the scaffold
   lacks one; a smoke `bun test` file proving the runtime boots and a feed call
   returns typed data with browser-constrained realizations (native excluded
   by capability, trace recorded).

4. **`apps/desktop/src/main.ts`** — desktop entry (the reference client): same
   runtime, DesktopCapabilities; smoke test proving native-mode realizations
   are selectable (via the resolver precedence trace) when the engine port is
   present (fixture engine port).

5. **`apps/mobile/src/main.ts`** — mobile entry: MobileCapabilities with
   OS-constrained background policy inputs (network class/charging injected);
   smoke test proving background completion decisions adapt (wifi-only +
   cellular fixture ⇒ typed pause decision surfaced).

6. **`parity.ts`** (shared) — `assertParity(runtimeA, runtimeB)`: a test helper
   proving the three runtimes expose IDENTICAL call surfaces (typed method
   parity + identical event vocabulary on the same fixtures) — the parity
   INVARIANT, machine-checked.

7. Tests: `apps/web/src/shared/*.test.ts` + per-app smoke tests (bun:test):
   - Capability profiles vs domain canPlay contract (assertions compile).
   - Runtime façade: golden feed + playback + library flows per platform.
   - Parity: three runtimes, same fixtures ⇒ same event vocabulary, same
     typed error taxonomy, same API surface.
   - Background policy adaptation on mobile profile.
   - Resolver trace differences per profile (web: native skipped with reason;
     desktop: native chosen when available).
