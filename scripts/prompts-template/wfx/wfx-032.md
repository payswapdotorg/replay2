## 3. Task packet

**WFX-032 — BYOM adapter.** STRUCTURED model scoring with POLICY ENFORCEMENT
for user-supplied models: the adapter wraps an arbitrary external scoring
function (injected — the real model is the user's; here the SEAM is the
deliverable) and enforces privacy, cost, output-schema, and safety constraints
around it. Realization: `packages/model-fabric/src/byom/`.

Build these modules (file names may differ; structure required):

1. **`byom.ts`** — `ByomModel` port (the seam): `{ id: string; version: string;
   privacyClass: "local-only" | "trusted-cloud" | "any-cloud"; costPerCall:
   number; score(input: ByomInput): Promise<unknown> }` — UNTYPED output
   deliberately (external models return whatever they return); the ADAPTER's
   job is to validate and shape it. `ByomInput` = the serialized
   RecommendationContext (candidate features included) MINUS fields redacted
   by privacy class (see redaction.ts).

2. **`redaction.ts`** — privacy enforcement (pure):
   `redactForPrivacy(ctx, privacyClass)`: `local-only` ⇒ full context;
   `trusted-cloud` ⇒ userId pseudonymized (deterministic salted hash — no
   reversible identifiers), session ids kept; `any-cloud` ⇒ pseudonymized +
   event payloads minimized (keep types/timestamps, drop free-text query
   strings). Returns typed `RedactionReport` listing every transformation
   applied — auditable, never silent.

3. **`enforce.ts`** — output validation + policy enforcement:
   - `validateByomOutput(raw): ValidationResult<RecommendationScore[]>` —
     strict schema: array of `{ itemId, score (finite number), explanations
     (string[]), confidence [0,1] }`; unknown fields tolerated but logged in
     the validation report; malformed ⇒ typed errors with paths.
   - `enforcePolicy(scores, policy)`: CLAMPS scores to a sane range, caps
     explanation count, marks confidence 0 when the model returned none —
     never fabricates scores: an empty/failed model response yields a typed
     `degraded` verdict that the caller (OS) sees, NOT fake zeros.
   - Cost ceiling: costPerCall × estimated calls vs policy maxCostPerOperation
     ⇒ typed refusal before invocation when over budget.

4. **`adapter.ts`** — `createByomAdapter(byom: ByomModel): RecommendationModel`:
   - `score(ctx)`: redact per privacy class → cost check → invoke byom.score →
     validate → enforce → return. Every step recorded in a `ByomTrace`
     (redaction report, cost check, latency estimate via injected clock,
     validation result, enforcement clamps) attached to a debug accessor, NOT
     to the scores (scores stay clean).
   - Failures: byom throw/reject ⇒ typed `ByomError` propagated as a Promise
     rejection the OS can catch (models may fail; the OS decides fallback —
     adapter never silently substitutes).

5. **`fabric.ts`** — `createByomProvider(byom): ModelProvider` — Fabric wrapper
   (tasks `recommendation`/`ranking`, privacy from byom class, routing + cost
   through the MERGED fabric APIs). Includes `registerByom(fabric, byom)` glue.

6. Tests in `packages/model-fabric/tests/byom.test.ts` (bun:test):
   - Redaction matrix: every privacy class × field — golden RedactionReports;
     no silent transformations; local-only untouched.
   - Output validation: well-formed, malformed (missing itemId, NaN score,
     non-array), tolerated-unknown-fields — typed results each.
   - Policy enforcement: clamping bounds exact; empty model response ⇒ typed
     degraded (NOT zeros); explanation cap; confidence-0 default.
   - Cost ceiling: over-budget ⇒ typed refusal, byom NEVER invoked (counting
     fake proves it).
   - Trace completeness: every stage present on the debug accessor.
   - Adapter failure: throwing byom ⇒ typed rejection; no substitution.
   - Fabric registration: tasks + privacy + routing through merged APIs.
