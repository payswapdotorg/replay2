## 3. Task packet

**WFX-015 — Local HTTP range/media gateway.** The local HTTP surface that serves
media bytes with byte-range semantics from the native-media layer, so standard
players (video elements, embeds) can stream. This item delivers the RANGE
SEMANTICS + request/response typing + a fully functional IN-MEMORY test server;
binding the gateway to the REAL engine is a later integration step.
Realization: `packages/native-media/src/gateway/`.

Build these modules (file names may differ; structure required):

1. **`request.ts`** — `RangeRequest` parsing: `parseRangeRequest(headers)`:
   - `Range: bytes=0-1023`, `bytes=0-`, suffix ranges `bytes=-500`, multi-range
     → SINGLE range only (multi-range returns typed `unsupported` with reason —
     deliberate scope cut, documented); `If-Range` ignored (typed in the trace).
   - Output: `{ kind: "full" } | { kind: "range"; start: number; end: number }`
     plus parsed `If-None-Match`/`If-Modified-Since` pass-through data.
   - Malformed `Range` headers (`bytes=abc`, inverted ranges, 0-length) → typed
     `RangeError` with the exact offending header value — NEVER a silent full-file
     fallback (players rely on status semantics).
   - Reuse/extend the MERGED WFX-004 `range.ts` parsing if its types already
     cover this — do NOT duplicate; import from `@wfx/native-media`.

2. **`response.ts`** — `buildRangeResponse(asset, request)`:
   - Full request → 200 + `Content-Length` + `Accept-Ranges: bytes` + ETag
     (deterministic hash of assetId+version) + `Content-Type` from asset metadata.
   - Range request → 206 + `Content-Range: bytes s-e/total` + `Content-Length`.
   - Range beyond EOF → 416 typed verdict with `Content-Range: bytes */total`.
   - `If-None-Match` match → 304 typed verdict (no body).
   - Pure: returns a typed `GatewayResponse` (status, headers, body descriptor
     `{ assetId; offset; length }`) — NO socket I/O here.

3. **`server.ts`** — `createGatewayServer(engine: NativeMediaEngine, opts)`:
   - `handle(req: GatewayHttpRequest): Promise<GatewayHttpResponse>` — the
     transport-agnostic handler: parse → resolve asset bytes via the engine
     service envelope (open/read/seek through the MERGED service API; bytes
     served from session range reads) → buildRangeResponse → serialize.
   - Engine/session failures map EXACTLY to the WFX-004 error taxonomy →
     HTTP statuses: NOT_FOUND→404, INVALID_RANGE→416, ENGINE failures→503 with
     typed error body (machine-readable JSON envelope + human message).
   - Concurrency-safe: one session per asset, reused across requests; idle
     sessions closed after `idleTimeoutMs` (deterministic, clock injected).
   - NEVER blocks: reads that need buffering await engine progress with a
     deadline → timeout is a typed 503 + engine `prioritize` hint for the
     requested range (deadline-aware pull, reusing the engine's
     `prioritize(deadlines)` surface).

4. **`test-server.ts`** — `startTestGateway(port)` — a REAL minimal HTTP server
   (Bun.serve or node:http — whichever the repo's governance permits; zero new
   deps beyond bun builtins) binding `handle` over a simulation-engine-backed
   in-memory asset store: deterministic synthetic assets (byte patterns), used
   by integration tests. Clearly typed as TEST infrastructure, never production.

5. **`bytes.ts`** — pure byte helpers if not already in the merged package:
   `contentRange(start, end, total)`, `etagFor(assetId, version)` (deterministic
   FNV-1a — no crypto dependency), `validateRangeBounds`.

6. Tests in `packages/native-media/tests/gateway.test.ts` (bun:test):
   - Range parse: every well-formed shape, every malformed shape (typed errors).
   - Response build: 200/206/304/416 golden headers for each case.
   - End-to-end through the test server: fetch with Range headers (Bun's fetch)
     against a simulation-engine asset — statuses, Content-Range, body bytes
     verified byte-exact.
   - Multi-range → typed unsupported.
   - Engine failure → 503 + typed JSON error body.
   - Deadline-aware: slow-buffering asset + short deadline ⇒ typed 503 with
     prioritize hint observable in the engine trace.
   - Idle session close after injected-clock advance.
