## DESIGN GUIDANCE (the Lead's calibration — bake these in)

- Docs are for BOTH humans and coding agents: every capability gets the roadmap's nine-part treatment (one-sentence explanation; conceptual model; minimal API example; SDK example where available; request/response schemas; execution lifecycle; security/policy notes; cost/latency considerations; common failures + remedies; link to the public contract). Machine-readable artifacts (OpenAPI-style schema, capability manifest, error-code table, env-var contract, rate/usage semantics) are FIRST-CLASS — a coding agent must discover the full integration path from files alone, no maintainer chat, no prose-only critical instructions.
- The quickstart is the spine: five minutes from zero to a first sandbox execution — auth, application, environment, credential, first Execution via SDK, result + evidence + cost retrieval. Copy/paste runnable against the supported sandbox path; every example compiles/typechecks in your battery.
- Every supported workload family (text, structured, RAG, tools/workflows, agents, voice/realtime, image, video, vision/VLM/audio, multimodal, 3D, browser/computer use, human review) gets a concrete example OR an explicit provider-gated/NOT-RUN marker — availability honesty is an acceptance criterion, and provider availability disclosure rules are documented themselves.
- The conceptual model section teaches the authority chain in developer terms: Execution (the primitive), policy-before-dispatch, capabilities, budgets/economics, sandbox isolation, verification + evidence — sourced from `spec/architecture.md` vocabulary, but written for outsiders.
- Production path: environment promotion (local→preview→staging→production), secret management, quotas, migration/rollback pointers — referencing the deployment surfaces DEP-001 owns (cross-link, never duplicate).
- Failure taxonomy + troubleshooting playbook: the error codes, the retry/idempotency semantics, the webhook signature verification + receiver idempotency guidance from the SDK, and honest provider-limitation behavior.
- Link/schema validation is AUTOMATED: a vitest test that walks your docs' internal + example links and validates the machine-readable schemas parse and match the wire contract types where mechanically checkable.
