## 3. What you are building (the shape)

A governed evaluation corpus + harness proving two mappings over the HFX-000
control plane, fully deterministic:

1. **IFC-Bench lane** (construction/BIM REASONING): question fixtures in the
   IFC-Bench taxonomy (property/quantity lookup, spatial composition, part-of /
   connected-to topology, classification questions) over deterministic in-repo
   building-model fixtures. Each question maps to the EXPECTED Evidence
   Envelope: the evidence items (with kinds from `EVIDENCE_ITEM_KINDS`), facts,
   assumptions and the bound evidence revision the answer must cite. The
   evaluated answer is checked for envelope integrity — an answer whose
   envelope cites evidence that does not exist, or asserts a fact absent from
   the bundle, must be classified a failure with the right closed-vocabulary
   kind.
2. **BIM-Edit lane** (OPERATION SEMANTICS): edit-task fixtures in the BIM-Edit
   taxonomy (create/update/delete elements; spatial and topological changes)
   expressed as natural-language-style commands AND as direct intent records,
   each expected to resolve to a normalized `EngineeringOperationIntent` /
   `EngineeringOperation` shape (typed parameters only). The harness evaluates
   the RESOLVED INTENT against the expected operation semantics WITHOUT
   executing unsafe changes: no fixture ever mutates authoritative state;
   evaluation compares normalized intents (typed parameters, targets,
   constraints), never fabricates geometry.
3. **AISE-specific negative cases** (mandatory, at least these four classes):
   - unavailable/missing geometry (the referenced element does not exist —
     expected: explicit failure, never a fabricated shape);
   - conflicting evidence (two evidence items disagree — expected: surfaced
     conflict, no silent resolution);
   - missing dimensions (an edit needs a quantity the bundle does not carry —
     expected: clarification/bounded refusal, no invented measurement);
   - invalid constraints (the edit violates a stated topological or unit
     constraint — expected: operation-semantic-failure with the violated
     constraint named).

  NOT the upstream dataset); question/edit fixtures; expected envelopes and

  providers registered through `createProviderRegistry` + `applyRegistryEvent`

  digest helpers); provenance manifests sealed + verified.
- **Harness** (`harness.ts` + tests): run a fixture (question or edit) through
  the fixture provider → `normalizeResult` → envelope/intent checks →

  test asserting the classified kind).
- **Golden fixtures** (`golden.test.ts` + fixture JSON): byte-stable expected
  outcomes (the tools/reasoning-eval expected-outcomes.json pattern); a test
  replays the corpus and byte-compares the classification digest.
- **Service/index** (`service.ts`, `index.ts` + tests): the evaluation entry —
  run the whole corpus, aggregate per-lane/per-kind counts, produce the
  summary record. Export the public surface from `index.ts` (types +
