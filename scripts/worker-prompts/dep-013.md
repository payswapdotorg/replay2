## DESIGN GUIDANCE (the Lead's calibration — bake these in)

- The playground is a PROJECTION surface: every run is a real execution through the public API with a sandbox environment spec admitted by the existing chain. You never bypass or reimplement policy/capability/budget admission.
- The workload-class picker renders from the SAME catalog the machine manifests carry. If a server-side projection route is needed to serve it to the console, it reads the capabilities/sandbox public barrels — one source of truth, zero drift. Verify single-sourcedness in a test.
- Choose → compose → run → inspect: the composer's input schema matches the class's advertised contract; inputs are constrained to synthetic data (the DEP-014 policy route when present, otherwise the deployment's advertised synthetic-data rules — enforce what exists, honestly state what doesn't); the run creates a real execution under a disposable-sandbox identity; the outcome deep-links into the execution explorer's public facts.
- Every catalog family appears in the picker. Families without live provider access render honest NOT RUN states naming the missing capability/provider contract — never hidden, never faked.
- Composition state is client-side and disposable: nothing typed into the composer persists beyond the browser session unless executed (then the execution record is the durable truth).
- Machine parity: every class links its copyable integration-kit example; an agent reproduces any run without the console.
- Honesty doctrine: missing facts render as honest unavailable states NAMING the missing public contract. Responsive + accessibility: keyboard paths for choose → compose → run → inspect, labeled controls, honest empty/error states. House test style (vitest, `tests/unit/**`).
