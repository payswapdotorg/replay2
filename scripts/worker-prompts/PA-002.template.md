## 4. Implementation shape (mirror the PA-008 closure discipline exactly)

1. **Domain read record** — `packages/domain-commerce/src/refund-read.ts`: a
   read-only `RefundRead` (or house-named) record per refund: the CLOSED state
   vocabulary mirrored from the aggregate (`pending` / `succeeded` / `failed` /
   `cancelled`, never collapsed, never merged with payment/invoice/order
   states — RL-LOCK-008), the closed reason-code label vocabulary, amount +
   currency (integer minor units), the parent payment reference, first-class
   freshness used DIRECTLY from `@roamlink/contracts` (never redefined), a
   fail-closed parse (duplicate ids, unknown states/fields, bad amounts fail),
   honest-state invariants, and NO write path (parse + vocabularies only — the
   authority fence gets its own test, as PA-008 did).
2. **App-kit mirror** — `packages/app-kit/src/api/refunds.ts`: `RefundView`
   (`state`, optional reason summary, amount/currency, freshness pairing) +
   the mirrored vocabulary constants, drift-guarded by ONE new wave4-a entry
   (mirrorFile `refunds.ts` ↔ ownerFile `refund-read.ts`); an older payload
   without the section parses to the honest null section (RL-LOCK-017); the
   order journey read gains the optional `refunds` section additively.
3. **Fake seeds** — the deterministic fake seeds the honest world by default
   (at least one order carrying a succeeded refund + one pending; at least one
   order with NO refunds — the honest empty section), and scenario seeds
   derive every state × at least one refund, plus one multi-refund (partial)
   payment case.
4. **Page section** — the order journey renders the refund section FROM THE
   READ ONLY: one row per refund with its state word, per-state fact, amount +
   currency, reason label, and freshness pairing (a stale read keeps its
   content PAIRED with the stale badge — the §14 discipline), the authority
   note naming where refund execution lives (upstream, in commerce operations)
   and the §15 support escape. An absent/null section renders the honest
   not-available state (the page's established pattern).
5. **Guard + doc flips** — (a) the rl115 F4 GAP probe flips IN PLACE to a
   closure probe (render the order journey, assert refund state IS exposed —
   the PA-009/PA-010 convention; the commerce-page side keeps asserting NO
   refund view vocabulary — that page stays out of scope by design);
   (b) the wave8-b CAP-B-REFUNDS structural guard flips: order-journey-page.ts
   MUST carry the refund view vocabulary, commerce-page.ts must NOT; (c) the
   wave8-b GAP tally chain comment goes 1 -> 0 (the last recorded GAP closes;
   F8 stays VERIFIED(proxy)) and the expected GAP count updates; (d) the audit
   doc's F4 record gains its CLOSURE (PA-002, VERIFIED) paragraph in the
   PA-008/PA-010 house style + the narration tally is reconciled.
