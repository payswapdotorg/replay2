## 3. The work

1. **The package** `tests/acceptance`: a Playwright-based (or equivalent)
   suite whose runner takes `ACCEPTANCE_BASE_URL` (+ demo login env vars
   per the demo roster) and executes the journey matrix below at TWO
   viewport classes (desktop 1280x800, mobile 390x844 — the bottom-nav
   breakpoint).
2. **The journey matrix** (every leg = one recorded level outcome):
   - login (the demo quick-action or credential form)
   - onboarding wizard walk (goal -> enroll device -> finish)
   - Goals (empty state -> create -> the honest read-first refusal state)
   - Devices (list -> detail -> capabilities -> SIM & Profiles)
   - eSIM actions (install/enable/remove through the rendered forms —
     record accepted-vs-executed honestly)
   - Connectivity (summary -> why -> evidence -> technical)
   - Activity (+ the notification-derived section's honest state)
   - Plans & Billing -> product -> order -> payment -> delivery progress
   - Support (contextual escape -> case creation -> case thread)
   - Workspace (the enterprise journey legs the runtime allows)
   - Admin console (navigation, SLO, Integration Health, the gated routes)
3. **The a11y/interaction checks** on every walked page: exactly one h1;
   no heading-level skips; interactive targets >= 44px; keyboard
   reachability (tab order sample + focus visibility); the skip link;
   the mobile bottom-nav presence at mobile width; forms submittable via
   keyboard.
4. **The mutation checks**: every rendered form submits through the real
   flow plane; the typed result panel (acknowledgment with command id +
   idempotency key, or the honest typed refusal) is asserted; the six
   levels are recorded per leg.
5. **The level report**: the runner emits a machine-readable JSON +
   human summary (per journey: the furthest level reached + the honest
   stop reason), and the suite exits 0 when every leg reached ITS honest
   reachable level (a leg stopped by an honest runtime limitation is a
   PASS with the limitation recorded — the exit contract is "no lies",
   not "everything executed").
6. **The self-test**: an offline selftest mode (no env → named skip; a
   dummy local fixture → the runner machinery exercises) so `pnpm check`
   can include the package without requiring the deployed URL.
7. **The closure note**: ONE dated additive note in the audit doc; ONE
   additive env-contract paragraph in `spec/deployment.md`.
