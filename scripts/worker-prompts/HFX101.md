## 3. What you are building (the shape)

A provider-neutral Layer-1 reconstruction benchmark lane with MapAnything as
the registered candidate, fully deterministic:

1. **Provider profile**: register MapAnything through the control plane —
   mandatory profile fields complete, capability declarations covering
   multi-image reconstruction, metric depth and registration (aligned with
   the Layer-1 capability vocabulary — declare ONLY what the lane's fixtures
   exercise), cost model + latency/resource profile metadata (`COST_MODELS`),
   license declaration `evaluation-only`. The profile enters the append-only
   registry via lawful events; its benchmark records are comparable
   (`benchmarkComparabilityKey`) with the existing reference/deterministic
   path so a future real-model run slots in without schema change.
2. **The corpus** (deterministic fixtures, in-repo): Layer-1 reconstruction
   scenarios over evidence bundles — multi-image capture sets (structured
   fixture frames with camera poses/intrinsics as data), metric-depth tasks,
   registration/alignment tasks between capture passes. Each scenario
   declares its evidence bundle WITH REVISION IDS and the expected CANONICAL
   outcome (metrics + uncertainty), expressed through the reality-eval
   scenario model's shapes (import and reuse its validators — do not fork
   the schema).
3. **Fixture doubles** for the model: deterministic in-repo stand-ins (the
   `providerFixture`/testkit pattern) with FOUR behavior classes —
   well-grounded (normalized depth/pose/registration outputs comparable to
   the canonical expectation, correct uncertainty), degraded-evidence
   (insufficient overlap/coverage → a capture-requirement/bounded-uncertainty
   outcome, NEVER silently-downgraded geometry), failing (provider error → a
   closed-vocabulary typed failure with an explicit non-ready/fallback
   state, never fabricated geometry), and unsupported-task (a task outside
   the declared capability set → explicit unsupported, never a guess). The
   double's behavior is data-driven per scenario.
4. **The behavior matrix** (mandatory, tested): grounded-pass;
   degraded-evidence (bounded, capture-requirements surfaced);
   failed-invocation (typed failure + explicit fallback, no fabrication);
   unsupported-task-combination (explicit unsupported). Every cell must have
   at least one fixture and one test that FAILS if the behavior regresses.
5. **The comparison record**: the SAME corpus evaluated through (a) the
   MapAnything double and (b) the existing deterministic/reference path (the
   reality-eval testkit's existing provider double) — per-variant outcome
   counts, geometry/registration/depth metric deltas vs the canonical
   expectations, latency/resource profile metadata, uncertainty
   characteristics, joined on the comparability key (the "provider
   comparison" evidence the work order demands).
