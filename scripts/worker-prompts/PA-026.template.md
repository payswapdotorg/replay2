## 3. The work

1. **The bindability survey first**: for each honest-NULL section
   (enrollment, policy, integrations): identify the owning domain service/
   store in @roamlink/enterprise, the persistence shape it needs, and the
   port the api service can bind it through. Record the map in your report
   (section -> source -> port | STAYS-NULL <reason> if truly unbindable).
2. **The bindings**: bind the enrollment journey store, the policy
   administration records and the integration status records through the
   service's construction (the shared persistence port where the domain's
   stores persist; the in-process domain services where that is the
   designed composition — follow how the domain's own verification suites
   compose them). The workspace read's sections then serve REAL state.
3. **The enrollment commands**: the enterprise enrollment journey commands
   (submit/verify/activate/reject/cancel — the domain's vocabulary) reach
   the command plane as mutation routes IF the app contract renders them
   (check apps/web for rendered enterprise actions; PA-023's parity law
   governs — a rendered action MUST have a real API route). If the web app
   does not yet render enrollment actions, do NOT invent routes — record
   the finding (the UI-journey gap belongs to a surface work order).
4. **The executor bindings**: where an enterprise command must EXECUTE
   (the enrollment transitions, the connector provisioning attempt), bind
   the domain's transition functions as executors on the worker seam
   PA-025 composed (the same bounded-tick path). The domain's pure
   functions + the bound store = the executed fact; the ledger records it.
5. **The end-to-end battery**: over the real composition — an enterprise
   actor's journey: workspace read (organization real) → enrollment
   submitted → EXECUTED via the tick → verified → active → the workspace
   read serves the live enrollment state → connector provisioned (PA-023
   route) → EXECUTED → the connector section serves the provisioned state →
   policy administered → the policy section serves the real record →
   integrations status → the integration section serves the real statuses.
   Plus the honest negatives: a personal tenant's workspace (organization
   null — a real fact); an unexecuted transition (submitted but not yet
   ticked — the read serves the submitted state, never the future one).
6. **The authorized e2e updates** (`tests/e2e/**`): the enterprise journey
   test gains the executed-state legs (the eight-step walk against the
   real composition with the tick advancing the commands); the honest

   PACKET.
