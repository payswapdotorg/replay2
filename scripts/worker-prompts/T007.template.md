## Your task

Implement the **control plane domain and service skeleton**: how Goals, ConstraintSets and Projects are authored, versioned, validated, and how a Project's lifecycle drives the rest of the system.

### packages/control-domain — control-plane domain (TypeScript, strict, zero runtime deps, hand-rolled guards)

- **GoalSpec**: the executable form of a user goal — objective (typed: e.g. absolute-return, risk-adjusted, research-question, capability-acquisition), horizon, success criteria as MEASURABLE predicates (references to metric definitions by id), allowed markets/data/actions (universe refs), risk-budget reference, execution-mode policy (shadow | paper | live-eligible — typed, defaulting to the least consequential)
- **ConstraintBundle**: a project's constraint sets (versioned), each with provenance (authored | compiled-from-natural-language — the compiled executable form is what evaluates; provenance records origin), activation timeline (from when to when), and severity. NOTE: the evaluator itself is T002's frozen lane — your bundle REFERENCES ConstraintSet ids; you define the bundle structure, activation windows, and evaluation ORCHESTRATION (which sets apply at a given time), delegating predicate execution to an injected evaluator interface (define the interface; tests provide the implementation)
- **Project lifecycle**: ProjectRecord with a guarded state machine — draft → active → paused → archived, plus terminal states (completed, abandoned); every transition is validated, timestamped, attributed (who/what triggered it) and append-only in a transition log (L15 lineage)
- **ProjectWorkspace**: the durable connections a project maintains — goal spec version, constraint bundle version, market/data universe refs, organization refs (opaque ids), experiment refs, decision refs, outcome refs, lesson refs. Lineage: every artifact reference records (added-at, added-by, superseded-by) — the project is the lineage spine
- **Tenant scoping (L12)**: every record carries a tenant id; cross-tenant access is structurally prevented (a ProjectStore keyed by tenant; lookups cannot escape their tenant) — tested explicitly
- **BudgetEnvelope**: compute/risk/data budgets as typed envelopes with consumption records (no enforcement of consumption here — that's runtime lanes; here: the data model + accounting helpers)

### services/control-plane — the service skeleton (library + CLI, no HTTP this wave)

- An in-memory (pluggable-store) ProjectService: create tenant → author goal spec → version constraint bundle → activate project → record artifact references → pause/resume → archive; every operation audited (who/what/when/before/after)
- Goal validation: measurable-predicate references resolve; horizon coherent; execution-mode policy present (fail-closed: missing policy = invalid)
- Constraint orchestration: given a timestamp, resolve WHICH constraint sets are active (activation windows); produce the evaluation plan (set ids + evaluator inputs) for the runtime to execute
- A `project-manifest.json` export format: the full lineage spine of a project (goal versions, constraint versions, artifact refs) — deterministic serialization (stable key order) for hashing

### contracts (docs live in your packages this wave — NO contracts/ dir)

Authoritative markdown docs inside `packages/control-domain/docs/`: GoalSpec contract (typed objectives, measurable criteria), ConstraintBundle + activation semantics, Project lifecycle state machine, ProjectWorkspace lineage model, tenant-scoping rules, manifest format.
