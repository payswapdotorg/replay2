## 3. The work — three findings, one document contract

### F1 — every web document gets its h1 (the shell title)

The web shell renders the app title as `<a class="shell-title">` — so every
document's first heading is the page h2. The admin shell already does it right
(`siteHeader`'s `el("h1", {}, appTitle)`). Fix the web shell the same way: the
title anchor becomes an h1-wrapped anchor (h1 > a.shell-title), keeping the
anchor semantics (href, class) and the visual weight (adjust the h1 wrapper in
`WARM_SHELL_STYLES` so the rendered result is visually equivalent — no font
regression: the h1 must inherit the anchor's size/weight discipline, not the
browser default).

Flip expectation (rl114-extended-a11y F1 probe): every RENDER_CASE has
`h1Count === 1` and `firstLevel === 1`.

### F2 — no level skips anywhere

Two skip classes exist today:

a) **The Connectivity disclosure subjects** (`disclosure.ts`): h4 subject
   headings directly under the h2 section context. Change the three
   `el("h4", ...)` to `el("h3", ...)` — the disclosure panel heading is a
   section-level heading (h2 section > h3 panel subject). This builder is
   shared with admin; the admin suite must stay green.

b) **The read-error and mutation-result panel headings** (`components.ts`):
   the panels lead the document body with h3 ("The request failed" ×2, and
   the mutation-result panel's "Command acknowledged" + its error twin).
   With F1's shell h1 in place these become h1 > h3 skips (and under a page
   h2 they read as mis-nested). Change these panel headings to h2: they are
   document-body-level headings that precede the page's own h2.

Flip expectations: the "no OTHER level skips" probe asserts ZERO skips across
all RENDER_CASES (the connectivity `h2->h4` entry disappears); the failed-read
probe asserts `firstLevel === 1` (shell h1 first) and the panel renders
`>The request failed</h2>`; the mutation-result probe asserts `firstLevel === 1`.

### F3 — the 44px touch floor reaches every interactive family

The audit names the unfloored families: the home fact-card action links
(".home-fact-action a"), the goal/device card links (".goal-card a", the
"Open this device" family), the journey "Manage goals" links, and the shell
indicator's link (".shell-indicator-link" — floored in `WARM_SHELL_STYLES`).
Give every one of them the house 44px floor, following the existing floored
families' implementation pattern (see how `.more-item-link` / `.order-link` /
`.support-escape a` carry `min-height` + the inline-block/flex + vertical
alignment discipline so the floor does not break the surrounding layout —
match the existing pattern exactly; do not invent a new floor mechanism).

Flip expectations (the frozen-enumeration probe): the app-layer floored
anchor set grows to include `.home-fact-action a` and `.goal-card a` (plus
the journey-link family under its real selector); the negative asserts
(`.home-fact-action a { font-weight: 600; }` without a floor;
`not.toContain('.goal-card a {')`) flip to floor-positive assertions; the
shell layer floors `.shell-indicator-link`.
