## Your task

Fill `packages/domain-core/` with the canonical, provider-neutral TRADING DOMAIN contracts and write the human-readable contract docs under `contracts/domain/`. TypeScript, strict, zero runtime dependencies, no `any`, no external validation libraries — hand-rolled type guards.

Required concepts (names may be refined, semantics may not be lost):

- **Goal** — objective, horizon, success criteria, allowed markets/data/actions reference, risk policy reference
- **ConstraintSet** — VERSIONED, executable predicates and limits over observations, state, actions and outcomes (a constraint is data + a predicate kind, not a prompt string; include limit-style constraints with numeric bounds)
- **Project** — the durable unit connecting goal, constraints, market/data universe, organization, experiments, decisions, execution, outcomes and lessons (identity, status, lineage references)
- **Instrument** — identifier, asset class, venue references, tick size/lot conventions where applicable
- **Venue** — identity, asset classes, capabilities
- **Order** — side, kind (market/limit/stop and extensible), time-in-force, quantity, price, instrument+venue reference, client order id; NO execution semantics here (that is T010/T019)
- **Position** — instrument, quantity signed, average entry price, realized/unrealized split available as data
- **Portfolio** — collection of positions + summary metrics as data (no PnL computation in this lane — types only)
- **Organization** — identity, membership references, communication topology reference, decision cadence (structural only; agent-body types belong to T003 — reference by opaque ids)
- **Decision** — point-in-time decision record with evidence capsule reference, alternatives considered, confidence
- **Outcome** — realized result linked to a decision/execution, with post-mortem reference
- **Lesson** — durable, provenance-bound learning record

Cross-lane rule: agent/body/substrate/possession types are T003's lane; market events/time protocol are T004's lane. Reference them ONLY by opaque string ids (e.g. `bodyVersionId`), never by importing their packages (they do not exist yet and must not be added to your deps).

`contracts/domain/` must contain a markdown contract per concept group: field tables (name, type, required, semantics), invariants, versioning rules, and one JSON example each. These docs are the authority the next 40 work orders code against — precision beats volume.
