## Your task

Implement the **Agent OS kernel**: the small, stable runtime primitive set that agent organizations are built on. Higher-level organization structure evolves ABOVE this kernel (T016's lane) — do not build team search, organization compilation, or learning here.

### packages/agent-os — the kernel (TypeScript, strict, zero runtime deps, hand-rolled guards)

The kernel primitives (exact names from the architecture):

```
SPAWN, TERMINATE, DELEGATE, REQUEST, PUBLISH, SUBSCRIBE, CHALLENGE, PROPOSE, APPROVE, EXECUTE, ESCALATE, OBSERVE, LEARN, REPORT
```

Required:

- **Kernel message contract**: a typed envelope (message id, kind, from/to instance refs, correlation id for request/response chains, timestamp, payload discriminator, in-reply-to). Every primitive is a typed message kind with its own payload schema + guards
- **Instance lifecycle**: SPAWN creates an instance handle from (possession ref + authority scope + parent) — the instance registry tracks lifecycle (spawning/active/suspended/terminated) with a guarded state machine (illegal transitions rejected with typed errors); TERMINATE is explicit and auditable
- **Addressing**: instance addresses, topic addresses for PUB/SUB (publish/subscribe with topic filters), request/response correlation
- **Authority scope enforcement (L8 foundation)**: every instance carries a DECLARED authority scope (what message kinds it may send, what topics it may publish, whom it may spawn); the kernel REFUSES out-of-scope operations with typed errors — this is the in-kernel seed of "models cannot bypass hard gates": a spawned instance simply cannot emit messages its scope forbids, regardless of what its substrate wants
- **CHALLENGE/PROPOSE/APPROVE**: the governance handshake primitives — a proposal is typed data, challenges reference proposals, approvals are recorded decisions with approver identity; never free-text magic
- **ESCALATE**: routed upward along the parent chain with escalation reason taxonomy
- **OBSERVE/LEARN/REPORT**: the observation sink (what the instance saw, point-in-time stamped), the learning-event channel (typed capability-gap/gradient/skill events — payloads are references, not model internals), and the report channel (structured, auditable)
- **Determinism aid**: the kernel is a message-passing system with an explicit delivery ordering policy (document it: per-sender FIFO; document what remains environment-dependent); an `InMemoryKernel` implementation with a deterministic clock injection point
- **Audit log**: every kernel operation appends an immutable, hash-chained audit record (prev-hash linkage) — the kernel's own transcript is tamper-evident

### services/agent-runtime — the runtime skeleton

A minimal library + CLI (no HTTP server this wave):

- Bootstrap an `InMemoryKernel`, register N instances (test-double possessions — a `ScriptedAgent` that replies per a script map), run a scenario (spawn -> delegate -> propose -> approve -> execute -> report), print the audit chain and verify its hash chain
- The runtime enforces scope at spawn time (a spawn request with an authority scope exceeding the parent's own scope is REJECTED)
