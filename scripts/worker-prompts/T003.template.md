## Your task

Fill `packages/agent-body/` with the contracts for the system's core abstraction and write the human-readable contract docs under `contracts/agent/`. TypeScript, strict, zero runtime dependencies, no `any`, hand-rolled type guards.

The core law (ARCHITECTURE-LOCK L2/L3):

```
Agent Instance = Agent Body Version + Cognitive Substrate + Possession Configuration + Environment + Runtime State
```

A model is a cognitive substrate. An Agent Body is the persistent, versioned trading capability composition possessed by that substrate. Bodies and models are separate: a model upgrade triggers compatibility testing, NOT body redevelopment. A persistent capability change creates a NEW Body Version; certified versions never mutate.

Required concepts (names may be refined, semantics may not be lost):

- **CognitiveSubstrate** — model identity (provider, model id, version), capability manifest (context window, modalities, tool use, structured output), cost/latency profile, substitution class (substrates that are candidates to possess the same bodies)
- **BodyVersion** — IMMUTABLE: semantic version, parent version lineage, capability composition containing mission, capabilities/skills, knowledge & tool policy, procedures, planning policy, delegation policy, authority/safety boundaries, evaluation/environment requirements, and a substrate compatibility manifest (required capabilities + constraints + tested substrate list with results); a certified flag and certification evidence reference
- **Possession** — the binding: BodyVersion + CognitiveSubstrate + adapter/config + runtime profile + environment profile + policy bundle; possession validity requires substrate satisfying the body's compatibility manifest
- **AgentInstance** — a possession operating at runtime: authority scope, parent/manager reference, runtime state handle (the state itself lives elsewhere — T006's lane), lifecycle status
- **Substitution/compatibility testing contracts** — a `compatibility` module: given a body manifest and a substrate manifest, produce a compatibility verdict (satisfied / violated-with-reasons); tested-substrate records bind results to evidence
- **Version lineage** — helpers to walk parent chains and assert no cycles, and a rule that a certified version is deeply frozen (type-level + runtime guard against mutation of the certified record)

Cross-lane rule: trading domain entities (Order, Portfolio, Goal…) are T002's lane and market events/time are T004's lane. Reference them ONLY by opaque string ids; never import their packages (they do not exist yet and must not be added to your deps).

`contracts/agent/` must contain a markdown contract per concept: field tables, invariants (immutability, possession validity, certification rules), the possession state machine, and one JSON example each. These docs are the authority for the Agent OS (T006) and the body forge (T017) — precision beats volume.
