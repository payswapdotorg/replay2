## The work

**Account credentials through the identity seam:**

1. **PasswordHasher seam (in packages/identity)**: a new module defining the `PasswordHasher` interface — pure computation contract (`hash(plain, salt) -> verifier`, `verify(plain, salt, verifier) -> boolean` style — design it honestly). NO crypto dependency inside identity (the package stays zero-dep, strict TS, no clock reads): identity only owns the SEAM + the password-credential RECORD shape (account/tenant binding, salt, verifier, injected timestamps).
2. **Credential records + storage**: durable password-credential records over the existing store/repository pattern in identity (the W100C durable record seam — mirror how session/principal records are shaped). Machine-stable refusal reasons for unknown-account vs wrong-password.
3. **Sign-up**: create account + workspace as founder WITH credentials — extend the existing workspace-lifecycle/create path so a signed-up founder has a password credential record; the product sign-up tab creates the account and opens the first session.
4. **Sign-in**: workspace + email + password verified against the stored verifier. The existing sign-in seam (currently tenantId+email only — see `product-session.ts` signIn) gains the password requirement. Wrong password / unknown account / expired session = machine-stable refusal reasons with frozen human words (extend `PRODUCT_REFUSAL_EXPLANATIONS` honestly).
5. **Sign-out**: already exists (revoke) — keep it true; make sure it also clears the persisted browser session.
6. **Persistent browser sessions**: the runtime persists the session token through an INJECTED session-store seam (interface in web-product types; `localStorage` implementation injected at the composition root — product-gate.tsx). Reload KEEPS the session honest (expiry still enforced via the resolve seam; corrupted/unknown/mismatched tokens fail closed to the gate). Never auto-login an expired or revoked token.

LAWS (violations = rejection):
- **Passwords never render** — no credential values (plain or verifier or salt) in any client payload beyond the verifier inputs flowing into the seam call; no password field that renders its value; type=password semantics.
- **Fail-closed throughout**: unknown tenant, unknown account, wrong password, expired/revoked/corrupted persisted token = machine-stable refusal + the gate; never fabricated success.
- **No clock reads** inside identity or the runtime — timestamps injected (the `now` seam already flows through product-gate).
- **Style ONLY through existing `fos-*` classes** — W120 owns every stylesheet in parallel. Markup structure may change (tabs, fields); classes must be existing ones.
- Sign-up/sign-in/sign-out flows get machine tests: sign-up → reload persists → sign-out clears; wrong password refusal; unknown account refusal; corrupted localStorage token fails closed; expired persisted token fails closed.
- All existing tests must pass — baseline **3265/0**. You will ADD tests (identity package tests + product session tests); the count grows.
