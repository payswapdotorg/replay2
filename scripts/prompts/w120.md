## The work

Adapt the interaction and visual QUALITIES of stripe.com into the FleetOS console design system:

1. **Light foundation with generous whitespace** — calmer surface hierarchy, more breathing room in paddings/margins/section spacing.
2. **Crisp 8px-radius cards and inputs** — move `--radius` to 8px (small radius 6px), soften shadow elevation (`--shadow` subtle, near-flat with a faint 1px border feel).
3. **Subtle gray borders with soft elevation** — hairlines become quiet cool grays rather than warm sand; surfaces approach white.
4. **Grouped light sidebar navigation + topbar with account area** — sidebar: grouped nav sections with small uppercase group labels, light background, active item pill; topbar: account area treatment (the session chrome's member chip / role area).
5. **`#635BFF` accent** for primary actions and focus rings (`--accent` family; derive a hover shade). Restrained semantic status colors — keep the existing semantic MEANING of each status token, just re-tune the hues to be calmer/more saturated-modern.
6. **Inter/system font stack** — `"Inter", -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, ...` in `--font` (and the document base in console-styles.css). No webfont loading (no dependency/no network) — the stack degrades gracefully.

LAWS (violations = rejection):
- **Adapt qualities — never copy Stripe branding, logos, marketing text, or pixel-exact layouts.** This is the same law as the ShareNet rule: qualities yes, identity theft no. Nothing in the output may be recognizably "Stripe's property".
- **The `fos-*` class CONTRACT is frozen**: every existing class name keeps its name and its semantic meaning. You may restyle what a class looks like; you may NOT rename, remove, or repurpose classes (W121's auth screens depend on them). You may ADD new classes if genuinely needed (prefix `fos-`).
- **No logic changes**: no state machines, no handlers, no data flow, no test-behavior edits. Pure visual adaptation (CSS values, markup structure only where the visual grouping demands it, e.g. wrapping nav items in a group container).
- Keep the stylesheet a deterministic frozen template literal — byte-identical across renders. Keep the reduced-motion rule.
- Shell tests (`apps/web/shell/src/index.test.ts`, render tests) assert token/rule PRESENCE — if an assertion pins an exact VALUE you are changing, update that assertion in the SAME commit (shell-owned tests are in your scope); never delete a test to make it pass.
- The lane-local token copies stay frozen; do not try to unify them (that is a later wave). The shell chrome + session chrome + document base is your whole canvas.
